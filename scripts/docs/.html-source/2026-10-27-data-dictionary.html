数据字典与运行配置存储

统一保存外部模型路径、API Key、运行参数和 root 密码哈希的加密数据层

HTML 源文件：scripts/docs/.html-source/2026-10-27-data-dictionary.html

数据字典是运行时配置的唯一登记入口，采用“命名空间 + 键”的数据模型。普通值直接保存；密钥和密码哈希先由 AES-GCM 加密，再写入 t_data_dictionary 表。管理端只显示键的元数据和“已配置”状态，不返回明文。

物理命名规范

对象规则示例
数据库表t_${业务名}，业务名使用小写单数英文和 snake_case。t_user、t_case、t_data_dictionary
数据库字段f_${业务名}，保留 snake_case 业务语义。f_id、f_username、f_display_name
物理主键每张表统一使用 f_id BIGINT 自增主键，只用于数据库内部关联和排序，不作为 API 标识。1、2、3
业务唯一键每张表另设一个唯一业务键，API、文件和审计引用使用该值，不使用物理主键。f_user_key、f_case_key、f_dictionary_key
Python 属性与 API 字段保持现有 snake_case，不附加数据库前缀。UserRow.display_name、JSON 字段 display_name
数据字典逻辑键仍使用点分业务键，不附加 f_；这是配置键而不是物理列名。integration/summary.base_url

核心模型

字段用途安全约定
namespace按功能域隔离配置，例如 auth、integration。命名空间与键组合唯一。
key稳定键名，例如 summary.base_url。键名可以公开，不能包含凭据。
value_type文本、整数、浮点、布尔、JSON 或密钥。写入时校验，读取时按类型解码。
value_text普通值原文或敏感值密文。敏感值不得进入日志、审计详情或 API 响应。
is_secret标识该值是否必须脱敏。管理端列表将 value 置空。
revision单个字典项或命名空间配置的并发版本。并发写入使用 409 提示刷新。

当前键空间

命名空间键内容
authroot.password_hashroot 的 Argon2 哈希，AES-GCM 加密保存；t_user.f_password_hash 只保留占位值。
integrationsummary.base_url、summary.model、summary.protocol外部总结模型的请求路径、模型名和接口协议。
integrationsummary.api_key外部总结 API Key 密文。
integrationsearch.provider_order、search.max_results、search.include_complaint网络搜索运行参数。
integrationsearch.*.api_key、search.google_cse.id、search.searxng.base_url各搜索服务商连接凭据或地址。
integration_meta.revision、_meta.updated_at、_meta.updated_by配置版本与审计元数据，不包含秘密值。

读写边界

  1. 管理员服务配置页继续作为外部模型和搜索 API 的正常维护入口；页面交互不变，后端保存位置改为数据字典。
  2. auth 与 integration 属于系统维护命名空间，通用字典接口拒绝直接改写，避免绕过认证和配置审计。
  3. 通用数据字典接口需要 data_dictionary:read 或 data_dictionary:manage 权限；医生账号没有这些权限。
  4. 敏感项读取只返回 configured=true，不返回密文或解密值；内部运行链路通过受控存储适配器解密。
  5. 数据库管理员修改 root 密码时，需要在数据字典中替换加密后的 auth/root.password_hash；应用接口仍保留“不允许重置 root 密码”的规则。

迁移策略

  1. 首次启动时，如果数据字典没有 root 哈希，则从现有 t_user.f_password_hash 读取旧值，加密后迁入 auth/root.password_hash，随后把用户表字段改为不可登录占位值。
  2. 如果数据字典已有 root 哈希，则环境变量和管理接口都不能覆盖它。
  3. 旧版 UUID 主键会先保留为对应业务键，例如 f_user_key、f_case_key、f_dictionary_key，再新建 f_id 自增主键；审计事件新增 f_event_key 并回填唯一值。
  4. 旧版 t_integration_setting.f_payload_json 存在时，普通字段转为普通字典项，API Key 密文按原加密格式迁入密钥字典项。
  5. 迁移后原表不再作为运行时主存储，仅保留为回滚和审计期间的兼容快照。

验收清单

  1. 数据字典表存在 namespace + key 唯一约束，敏感项标记为密钥类型。
  2. 外部总结路径、模型名、搜索顺序和全部 API Key 均可在字典中定位，但 API 响应不含明文。
  3. root 哈希迁移后，t_user.f_password_hash 不再保存可登录哈希；数据库字典中的哈希仍可完成 root 登录。
  4. 普通命名空间可以按权限读写，系统维护命名空间不能通过通用接口绕过专用流程。
  5. 并发更新返回 409，审计事件覆盖写入和删除动作。
