唯一管理员与医生账号开户流程

固定 root 管理员、管理员创建医生、禁止自助注册及前后端接口边界

HTML 源文件：scripts/docs/.html-source/2026-10-27-auth-account-provisioning.html

本页定义账号体系的产品规则和工程契约。权限判断以后端为准；前端只负责隐藏或展示操作，不能作为授权边界。

账号规则

规则系统行为实现位置
唯一管理员管理员账号固定为 root；服务启动时创建或纠正该账号，并把其他历史管理员降为医生。启动引导、用户存储、管理接口
固定管理员口令APP_BOOTSTRAP_ADMIN_PASSWORD 只在 root 首次创建时使用；root 已存在后，环境变量、重启和应用接口都不能覆盖密码。密码哈希保存到数据字典的加密项，唯一变更路径是直接更新该数据库记录。启动引导、数据字典
医生开户只有登录的管理员可以创建医生；创建动作要求显示名、登录名和初始密码。POST /api/v1/admin/users
禁止注册不提供注册页面，也不提供注册 API；/api/v1/auth/register 返回 404。前端路由、FastAPI 路由
root 保护root 不能停用、不能通过后台重置密码、不能通过账号安全页修改密码；应用层没有修改 root 密码的通道。管理接口、密码接口、账号页面
医生生命周期管理员可以查看医生、启停账号、重置密码；重置密码会撤销该账号全部会话。管理接口、访问审计

后端逻辑

  1. root 不存在时，应用要求配置 APP_BOOTSTRAP_ADMIN_PASSWORD，把该值哈希后加密写入数据字典完成首次创建。
  2. root 已存在时，引导流程只确保角色为管理员、状态为启用并同步固定显示名；已有哈希会迁移到 auth/root.password_hash，之后不再读取 t_user.f_password_hash。
  3. 管理端创建账号时忽略客户端角色字段，后端固定写入 doctor；请求包含额外角色字段时返回 422，防止越权提升。
  4. 账号更新只允许修改显示名与启用状态，不接受角色字段；root 的停用请求返回 409。
  5. root 的后台密码重置和自行改密请求均返回 409；唯一变更通道是数据库直接更新数据字典中的加密哈希；医生密码重置成功后撤销该医生全部会话。
  6. 创建、启停、重置密码、登录成功与失败均写入 t_auth_audit_event，审计记录不包含密码明文。

前端逻辑

页面用户流程关键约束
管理员登录管理员从 /admin/login 进入，账号输入固定为 root。登录接口仍复核管理员角色，不能由医生入口越权进入。
医生账号管理员在 /admin/access 查看账号、创建医生、启停和重置密码。页面不提供角色选择、不提供管理员创建入口、不提供注册链接。
医生登录医生使用管理员分配的账号进入 /login。医生不能访问账号列表、审计或管理员服务配置。
账号安全医生可修改自己的密码并查看会话；root 显示为受系统保护的固定账号。前端拦截只是提示，后端仍返回 409 进行最终校验。

接口契约

方法路径权限行为
POST/api/v1/auth/admin/login公开但仅管理员root 登录并签发双 token
GET/api/v1/admin/usersuser:read返回管理员和医生账号，root 使用 is_root=true 标记
POST/api/v1/admin/usersuser:manage创建医生账号；不接受 role 字段
PATCH/api/v1/admin/users/{id}user:manage修改显示名或启停状态；root 不可停用
POST/api/v1/admin/users/{id}/passworduser:manage重置医生密码并撤销该医生会话
POST/api/v1/auth/register无不存在，返回 404

验收清单

  1. 系统中只有 root 一个管理员账号；历史管理员账号在启动后不再具有管理员角色。
  2. 未登录用户无法访问任何账号管理接口；医生访问管理接口返回 403。
  3. 管理员创建医生成功，账号角色固定为医生，新医生可以从医生入口登录。
  4. 任何客户端提交管理员角色创建请求均不能生成第二管理员。
  5. root 停用、重置密码和自行改密请求均失败；改环境变量后重启，数据字典中的 root 密码哈希保持不变。
  6. 直接更新数据字典 auth/root.password_hash 的加密值后，新密码能够登录；应用重建容器不会把密码恢复到环境变量值。
  7. 前端不存在注册入口；直接请求注册接口返回 404。

数据库修改约定

t_data_dictionary 中 auth/root.password_hash 保存的是经过 AES-GCM 加密的 Argon2 密码哈希，不是明文。数据库管理员更新前必须使用项目当前密码实现生成新哈希，再用部署主密钥加密后更新该记录；t_user.f_password_hash 只保留不可登录的占位值，应用启动、环境变量变更、管理员后台和账号安全页都不能改写 root 的现有哈希。

后续开发边界

账号体系不采用自助注册、邀请码注册或邮箱注册。后续新增账号字段时，仍应保持“管理员开户、医生使用”的主流程，并在新增字段通过后端白名单后才能进入页面。如需轮换 root 密码，只能由数据库管理员直接更新数据字典中的加密哈希；不得增加第二个管理员账号，也不得通过应用接口或环境变量覆盖现有密码。
