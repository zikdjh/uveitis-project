系统鉴权与权限体系

双令牌无感刷新、角色权限、CSRF、账号管理和审计边界

HTML 源文件：scripts/docs/.html-source/2026-10-26-auth-access-control.html

后端是唯一授权边界。前端路由和导航只控制可用界面，所有病例、知识库、系统运行和账号接口均在 FastAPI 服务端复核当前会话、账号状态与权限。

角色与权限

权限医生系统管理员主要接口
case:read允许允许病例列表、详情、影像读取
case:write允许允许建档、影像上传、启动分析
case:review允许允许医生复核与最终记录
knowledge:read允许允许知识检索与索引状态
knowledge:write禁止允许知识文档写入
system:read允许允许运行概览
system:manage禁止允许数据库与会话存储检查
integration:read禁止允许读取服务地址、模型、掩码状态与搜索顺序
integration:manage禁止允许更新服务密钥与配置、执行配置或连通性检查
user:read / user:manage禁止允许账号列表、创建、角色、状态与密码重置
audit:read禁止允许鉴权审计记录

外部服务配置权限

外部 API 与网络搜索 API 统一由系统管理员配置。医生保留 system:read 以查看运行概览与“总结/搜索是否启用”，但访问 /api/v1/admin/integrations 返回 403，不能读取地址、模型、搜索顺序或服务商配置状态。

  • GET /api/v1/admin/integrations 只返回公开展示字段；API Key 只返回是否已配置与固定文案提示，不回传原文或可逆值。
  • PATCH /api/v1/admin/integrations 使用 expected_revision 防止两名管理员互相覆盖，冲突返回 409。
  • 密钥使用 AES-GCM 加密后保存在 integration_settings；生产环境缺少 APP_INTEGRATION_SECRET_KEY 时拒绝启动。
  • 更新配置写入 integration_config_update 审计事件；审计只记录版本和操作，不记录密钥。
  • 外部总结的临床文本发送和网络搜索的主诉发送是两个独立开关，默认关闭；原始影像不发送。

登录与会话

医生与管理员使用独立登录入口。医生入口 /login 只接受医生账号，管理员入口 /admin/login 只接受管理员账号；服务端分别在 /api/v1/auth/login 与 /api/v1/auth/admin/login 复核角色，跨角色凭据校验成功也不能创建会话。管理员后台依赖 PostgreSQL 保存病例、账号、审计和服务配置；应用源码与测试均不使用 SQLite。

  1. 登录失败按“账号 + 来源 IP”在 Redis 中计数，默认 15 分钟窗口最多 5 次；达到阈值后返回 429。
  2. 成功后签发短期访问令牌和长期刷新令牌。访问令牌默认 15 分钟，刷新令牌默认 30 天。
  3. Redis 仅保存两个令牌的 SHA-256 指纹，不保存浏览器可见的原始令牌。
  4. 访问令牌 Cookie 使用 HttpOnly、SameSite=Lax 和可配置的 Secure 属性；刷新令牌 Cookie 进一步限制为仅发送到刷新接口。
  5. 访问令牌失效时，前端通过单一并发锁调用 POST /api/v1/auth/refresh，成功后自动重放原请求而无需用户重新登录。
  6. 每次刷新都会同时轮换访问令牌和刷新令牌，并为短暂并发保留刷新宽限期；退出、改密、角色变更和账号停用会撤销整组令牌。
  7. 服务端保存会话创建时间、最近活动时间、刷新到期时间、来源 IP 和客户端标识，并支持查看与撤销其他会话。
  8. 账号停用、角色变更、管理员重置密码或用户修改密码后，相关旧会话被撤销。

CSRF 与浏览器调用

双令牌配合双提交 CSRF 校验。登录后服务端签发访问令牌、刷新令牌和可读的 CSRF Cookie；前端对 POST、PATCH、PUT、DELETE 请求自动附加 X-CSRF-Token。凭证请求显式使用 credentials: include，当前部署约定为同主机、不同端口；改用跨站域名时需要同步调整 Cookie 域、SameSite、CORS 与 CSRF 方案。

账号管理

  • 管理员可创建医生或管理员账号，修改显示名、角色和启用状态。
  • 密码最少 12 位。管理员重置密码后撤销该账号全部会话。
  • 不能停用当前登录账号；系统始终保留至少一个启用的管理员。
  • 医生不能读取账号列表、管理账号或查看系统基础设施状态。

审计与安全响应头

登录成功、登录失败、登录限流、令牌刷新、退出、会话撤销、密码修改、密码重置、账号创建和账号更新均写入 auth_audit_events。API 响应统一加入 X-Content-Type-Options、X-Frame-Options、Referrer-Policy 和权限策略响应头；鉴权与管理接口不缓存。

运行配置

APP_ACCESS_TOKEN_TTL_SECONDS=900
APP_REFRESH_TOKEN_TTL_SECONDS=2592000
APP_REFRESH_ROTATION_GRACE_SECONDS=30
APP_LOGIN_MAX_ATTEMPTS=5
APP_LOGIN_WINDOW_SECONDS=900
APP_TRUST_PROXY_HEADERS=false
APP_COOKIE_SECURE=true
APP_BOOTSTRAP_ADMIN_USERNAME=admin
APP_BOOTSTRAP_ADMIN_PASSWORD=replace-before-deployment

管理员后台要求配置 APP_DATABASE_URL，缺失时拒绝启动；app.asgi:app 是生产 ASGI 入口，仓储只接受 PostgreSQL。会话和登录限流依赖 Redis，会话数据保存在 Redis，而不是在本地建立第二套数据库。部署环境应启用 HTTPS，保留示例中的 APP_COOKIE_SECURE=true，同时将引导账号密码替换为随机强密码。

主要接口

  • POST /api/v1/auth/admin/login：管理员专用登录入口，仅接受管理员角色
  • POST /api/v1/auth/login、POST /api/v1/auth/refresh、POST /api/v1/auth/logout、GET /api/v1/auth/me
  • GET /api/v1/auth/sessions、DELETE /api/v1/auth/sessions/{id}、POST /api/v1/auth/sessions/revoke-others
  • POST /api/v1/auth/password
  • GET|POST /api/v1/admin/users、PATCH /api/v1/admin/users/{id}、POST /api/v1/admin/users/{id}/password
  • GET /api/v1/admin/audit-events
