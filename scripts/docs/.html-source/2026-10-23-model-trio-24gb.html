24GB 核心模型方案

Qwen、补充决策模型与 BGE-M3 的三模型方案

HTML 源文件：scripts/docs/.html-source/2026-10-23-model-trio-24gb.html

核验日期：2026-10-23 · 数据来源：HuggingFace API / GitHub API / 模型卡与 LICENSE 现场读取 · 项目：葡萄膜炎辅助诊断

确定方案

核心链路：Qwen3.5-4B 做多模态理解，BAAI/bge-m3 在 CPU 上生成向量，zvec 提供本地嵌入式检索索引。

第一阶段先完成病例结构化、影像理解、证据检索、安全校验与医生复核闭环。BGE-M3 不占用显卡，zvec 与 FastAPI 同进程运行，部署压力集中在多模态模型。

补充决策：Intern-Decision-4B 默认关闭，只有真实脱敏病例、医生确认的决策标签和独立评测增益达标后才按需启用。Kev-4B 仅作为对照，不默认常驻。

24GB 显存预算

Qwen3.5-4B FP16
约 9-10 GB
BGE-M3（CPU / FP32）
显卡 0 GB
启用补充决策后的可用余量
约 11-13 GB

粗算规则：

  • FP16 / BF16：参数量 × 2 字节 + 运行时与 KV/激活缓存。
  • 8-bit / Q8：参数量 × 1 字节 + 运行时与 KV/激活缓存。
  • 4-bit / Q4：参数量 × 0.5-0.6 字节 + 运行时与 KV/激活缓存。

BGE-M3 在项目后端使用 CPU 推理，不占显存。补充决策模型是条件启用项；即使未来启用，也应与多模态模型顺序运行、分时加载或独立部署，避免同时常驻多个 4B 级模型。

核心与补充模型

模块 模型 参数量 许可 模态 / 任务 说明
多模态 Qwen3.5-4B 4.66B Apache 2.0 文本 / 图像 多模态理解、影像描述、结构化抽取。Apache 2.0，适合生产。
补充决策 Intern-Decision-4B 约 4B Apache 2.0 文本 / 图像 → typed decision Jev-like 决策模型，支持 choice、score、noul。默认关闭，通过数据和评测门槛后再评估。
向量 BAAI/bge-m3 约 0.57B MIT 文本 → 向量 轻量、下载量高、生态成熟，适合病历/指南/文献检索。本地后端固定使用 CPU。

常驻部署组合

方案 组合 显存压力 适用
P0 核心闭环 Qwen3.5-4B + BAAI/bge-m3（CPU）+ zvec 约 9-10GB 先完成影像理解、证据检索、安全校验和医生复核。
P1 条件补充 核心闭环 + Intern-Decision-4B 约 18-23GB 仅在决策数据、JSON 合法率、独立测试增益和医生评审通过后启用。
P0 备选 Kev-4B（基于 Qwen3.5-4B） 约 8-11GB 文本-only 决策或自有数据微调；建议换装或 Adapter 方式使用。
P1 精度升级 Cloudflare Clef-flash 9.4B + Qwen3-Embedding-4B 约 22-26GB 决策和检索质量更强，但需要分时运行或量化。
P1 多模态升级 Qwen3-VL-8B-Instruct + Qwen3-Embedding-4B 约 20-26GB 影像理解更强，但不要同时加载 9B 级决策模型。

替代与升级选项

模块 模型 说明
多模态升级 Qwen3-VL-8B-Instruct Apache 2.0，8.8B，精度更高，但 24GB 卡上要与决策模型分时运行。
决策升级 Cloudflare Clef-flash 9.4B，Apache 2.0，Jev-compatible，多模态。可作补充决策的高精度对照，但需分时运行或量化。
决策备选 Kev-4B Apache 2.0，文本-only 决策，适合用自有标注数据训练。
向量升级 Qwen3-Embedding-4B Apache 2.0，4.02B，检索质量更强，但会吃掉大量显存。
向量备选 BAAI/bge-m3 MIT 许可，社区使用广泛，适合中文与多语言文本检索。

下一步清单

  • 先完成核心闭环，补充决策保持 APP_DECISION_ENABLED=false。
  • 先用 Qwen3.5-4B 跑通影像 + 文本理解。
  • 用本地 CPU BAAI/bge-m3 和 zvec 建病历/指南/文献向量库。
  • 先积累真实决策标注、独立测试集和医生评审结果，再决定是否启用 Intern-Decision-4B。
  • 仅当补充决策有稳定增益时，再验证 Kev-4B 对照或换装方案。
