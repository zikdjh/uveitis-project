模型评估与推理说明

本地评估、冻结测试、显存限制与推理边界

规范入口：qwen3.5-4b/README.md

更新日期：2026-10-26

本页说明 Qwen3.5-4B 原型如何从训练产物进入本地评估，以及当前运行服务实际具备的能力边界。训练流程、基座、数据和 adapter 统一位于 model/training/；本目录只管理运行、评估和部署。

当前能力

  • qwen3.5-4b/app/ 提供基座、adapter 健康检查，并通过 POST /v1/judge 执行 Qwen3.5-4B 结构化辅助观察；结果固定要求医生复核，不构成完整诊断。
  • qwen3.5-4b/code/local_qwen4b_eval.py 支持冻结测试集生成式评估、严格 JSON 解析、分任务指标、按类别均衡抽样、预测保存和中断续跑。
  • qwen3.5-4b/scripts/run_local_4060_eval.ps1 是 Windows 本地入口。
  • 运行侧只读取训练产物，不复制基座权重，也不修改训练记录。

2026-10-26 已完成第 20 步候选的 16 条四类均衡受控推理 smoke，并完成真实 POST /v1/judge 本地烟测。服务使用 4-bit NF4 基座和 adapter，首次请求约 22 秒，热请求约 2.4–3.6 秒。本轮未启动 Modal，也未新增 Modal 费用。

健康检查

从项目根目录使用已验证的 CUDA 运行环境启动服务。首次有效请求才加载 4-bit 基座与 adapter，因此冷启动超时应高于普通 API：

cd qwen3.5-4b
$env:MODEL_RUNTIME_UPLOAD_ROOT = (Resolve-Path '..\model\training\datasets\training').Path
$env:MODEL_RUNTIME_INTERNAL_TOKEN = 'replace-with-shared-token'
..\.venv-runtime-smoke\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010

在 qwen3.5-4b 目录检查健康状态并发送一个受控请求。以下请求使用训练图像检查链路，不能作为准确率证据：

Invoke-RestMethod http://127.0.0.1:8010/health
Invoke-RestMethod http://127.0.0.1:8010/v1/models

$body = @{
  task = 'oct_aux_4class'
  case = @{
    case_id = 'runtime-smoke'
    images = @(@{
      id = 'CNV-1016042-142'
      kind = 'oct'
      local_path = (Resolve-Path '..\training\datasets\training\data\13_zhanglab_oct\13_zhanglab\ZhangLabData\CellData\OCT\train\CNV\CNV-1016042-142.jpeg').Path
    })
  }
} | ConvertTo-Json -Depth 6

Invoke-RestMethod `
  -Uri http://127.0.0.1:8010/v1/judge `
  -Method Post `
  -Headers @{'X-Internal-Service-Token'='replace-with-shared-token'} `
  -ContentType 'application/json' `
  -Body $body

ready 表示基座和 adapter 文件可定位；degraded 表示路径缺失。响应包含标签、发现、置信度、adapter SHA256、时延、生成截断标志与显存峰值，并固定带 requires_human_review=true、research_use_only=true。/v1/models 仍只是模型角色索引，不表示临床部署。

本地评估

先用每类 4 条验证均衡评估和四类输出：

.\qwen3.5-4b\scripts\run_local_4060_eval.ps1 `
  -AdapterDir 'model\training\assets\qwen3.5-4b\local-4060-oct-focus-cont-20261025-01\best_adapter' `
  -OutputDir 'model\training\assets\qwen3.5-4b\eval-oct-step20-runtime-smoke-20261026-01' `
  -Tasks 'oct_aux_4class' -SamplesPerClass 4

-SamplesPerClass N 按 task + label 确定性取前 N 条；-MaxSamples N 仍是按排序取前 N 条。两者互斥，实际抽样模式和各类数量会写入结果清单。

续跑冻结基线时，输出目录必须指向原评估目录，且不要添加 -Overwrite：

powershell -NoProfile -ExecutionPolicy Bypass -File `
  'qwen3.5-4b\scripts\run_local_4060_eval.ps1' `
  -AdapterDir 'model\training\assets\qwen3.5-4b\local-4060-grouped-cont-20261025-01\best_adapter' `
  -OutputDir 'model\training\assets\qwen3.5-4b\eval-oct-step20-vs-step100-20261025-01\step100' `
  -Tasks 'oct_aux_4class'

评估器只读取冻结测试图像和 manifest 元数据，不参与训练、学习率调整或 checkpoint 选择。不要把测试结果回写训练标签。

本地硬件边界

RTX 4060 Laptop 8 GB 已完成 4-bit NF4 QLoRA 训练实测，正式训练峰值分配 5.45 GiB、峰值保留 5.69 GiB。训练配置限制为图像像素 65,536、最大序列 256、micro-batch 1、梯度累积 4。

真实运行服务的常驻 NVIDIA 占用约 3.5 GiB，单图推理峰值分配 3.275485 GiB、峰值保留 3.355469 GiB；8 个并发请求经串行保护全部返回 HTTP 200，最慢约 14 秒，无 OOM。并发数字包含排队时间，不是吞吐量指标。加载基座、adapter 和 processor 仍要求无其他大型 GPU 进程占用显存；推理和训练不应在同一 GPU 并行执行。

服务端图像预处理与训练/评估保持一致：原图通过解码像素上限保护后直接交给 processor，由 processor 按图像像素预算缩放。显存峰值字段是本次进程自上次请求以来的 PyTorch 峰值统计，不替代系统级 GPU 监控。

预处理修正后的复测请求耗时 3.363 秒、峰值保留 3.355469 GiB，adapter SHA256 不变。该请求读取一张标签为 CNV 的训练图，模型返回 DRUSEN，置信度为 0、impression 为空；因此当前输出可用于检查运行链路和结构化契约，不能作为分类准确率或置信度可信度的证据。

输出约定

评估结果包含 eval_manifest.json、eval_metrics.json、eval_summary.json 和逐样本预测文件。中断时保留 .partial.jsonl，下一次从已有预测继续。正式结果必须保留 adapter 指纹、manifest 指纹、selection 指纹、抽样模式与类别数、任务集合、样本数、运行耗时和显存峰值。

模型运行侧的临时结果放入 qwen3.5-4b/ 或 outputs/；需要长期保留的评估证据应归档到 model/training/assets/qwen3.5-4b/<run-id>/，并在训练产物索引中登记。

推理边界

当前模型是科研原型，只能输出辅助观察和结构化候选，不构成诊断、治疗或用药建议。接入业务链路前仍需完成：

  • 冻结测试集完整评估与错误来源分析。
  • 患者级或来源级独立验证。
  • 医生复核、拒答和升级规则。
  • API 输入脱敏、审计日志和模型版本锁定。

补充决策模型仍默认关闭。只有真实脱敏病例、医生确认标签、独立测试集和增益证据齐备后，才进入条件实验。
