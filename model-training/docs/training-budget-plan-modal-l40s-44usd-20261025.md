## 3. 本月：Qwen3.5-4B 第一阶段

### 3.1 时间安排

| 阶段 | 内容 | 时长 | 预算 |
|---|---|---:|---:|
| Q0 | Modal 镜像、模型加载、单 batch smoke test | 0.5 小时 | $1.42 |
| Q1 | 小规模零样本基线 | 0.2 小时 | $0.57 |
| Q2 | Qwen3.5-4B QLoRA 第一阶段 | 2.6 小时 | $7.38 |
| Q3 | holdout 评估、adapter 导出、checkpoint 校验 | 0.5 小时 | $1.42 |
| 合计 |  | 3.8 小时 | $10.79 |

训练过程设置 20-30 分钟 checkpoint、2.6 小时硬超时、验证损失 early stopping 和最多连续 3 个样本异常即终止。到时间上限即停止，不为了“跑满 epoch”继续消耗额度。

第一阶段使用 `448 x 448` 最大像素、`1024` token、micro-batch 1、梯度累积 4。2026-10-25 已完成 150 步正式 run；第 100 步验证损失 `0.027432` 最低，第 150 步回升到 `0.031464`。因此不再按旧计划盲目扩充到 `1,800-3,000` 步，下一次训练必须先补 01 的难例和数据质量，再重新确定步数。每个任务和每个标签必须在训练集和验证集里出现，验证集只从 `train` 行确定性切分，固定 test 不参与训练或选模。

### 3.2 数据集

### 3.3 本月验收门槛

只有同时满足以下条件，才进入下月第二阶段：

- smoke test 能完成前向、反向和 checkpoint 保存。
- Qwen3.5-4B adapter 在 01、02、03 的固定 holdout 上均有可复现结果。
- 01、02、03 之外，13 OCT 辅助任务必须单独报告，不能把辅助类别当作葡萄膜炎诊断结果。

- 已记录每个数据集的来源、去重状态、切分规则和不能宣称的能力边界。
- 与零样本基线比较后，至少专项任务不出现明显退化。

如果 smoke test 失败或显存不稳，优先减少图像分辨率和序列长度，不追加购买大模型时间。

### 4.3 补充决策模型的启用门槛

当前下载数据没有足够真实的医生处置标签，因此 Intern-Decision 不是无条件训练项。后端默认 `APP_DECISION_ENABLED=false`，未启用时分析流程直接进入安全校验和人工复核，不影响核心检索闭环。只有满足以下门槛才启动 D0-D2：

- 至少 300 个脱敏病例，建议 300-500 个训练病例。
- 至少 80 个验证病例和 80 个独立测试病例。
- 每例包含病例摘要、人工审核的影像描述、检索证据和医生确认的处置选择。
- 目标字段统一为 `choice`、`score`、`noul`、`requires_human_review`。
- 按患者切分，且病例摘要、影像和证据之间不存在跨集泄漏。

建议的 `decision_sft` 格式：

```json
{
  "case_id": "case_0001",
  "input": {
    "summary": "年龄、性别、主诉、病程、既往史和关键检查",
    "vision": "经医生审核的影像描述",
    "evidence": ["指南条目", "文献段落", "相似病例"]
  },
  "target": {
    "choice": "受约束的处置选项",
    "score": 0.0,
    "noul": "在证据边界内的说明",
    "requires_human_review": true
  }
}
```

Intern-Decision 训练配置：

- 4-bit QLoRA，LoRA rank 16。
- 最大序列长度 2048，稳定后可试 3072。
- micro-batch 1，梯度累积 16。
- 3-5 epochs 或 2 小时硬超时，取较早的早停 checkpoint。
- 只训练语言层 adapter，不在此阶段训练图像编码器。

如果 11 月前拿不到合格病例和医生确认标签，D0-D2 不启动，E0 也只评估核心链路。这 4.5 小时优先用于 Qwen 的独立测试和错误分析，剩余额度保留；不能用 ODIR 的诊断关键词自动生成 `choice`、`score` 或医生决策，也不能用合成标签制造“补充模型已验证”的结论。

补充决策启用前至少应证明：

- 固定测试集上相对“仅感知 + 检索 + 医生复核”的基线有一致增益。
- 决策 JSON 合法率和拒答行为可复现。
- 误诊代价、证据引用和人工升级路径经过医生评审。

## 6. 节省额度的执行要求

1. 在本地完成解压、去重、切分、图像缩放和 manifest，Modal 只接收已筛选的训练包。
2. 训练包只放约 12k-17k 张图，不上传 63 GB 全量数据和无用的预处理副本。
3. 模型、图像缓存和 adapter 放在持久 Volume；代码镜像固定版本，避免每次重新安装。
4. 训练和评估分成两个 Modal 函数，评估时只加载 adapter 和必要的 holdout。
5. 关闭 warm container、定时任务和长期在线 GPU 服务。
6. BGE-M3 索引在本地 4060 或 CPU 上建立，不占用 Qwen3.5-4B 的 L40S 训练额度。
7. 每次 Modal 启动前打印 `max_runtime`、数据规模和预计成本，超过上限自动停止。

2026-10-25 的实测补充：不要在训练容器内启动嵌套 Modal 评估函数。该路径可能生成额外 GPU 作业，失败时还可能被训练循环误认为样本异常。正确流程是只训练并保存 checkpoint，等训练 app 完全停止后，再单独运行评估 app；每次停止都用 `modal app stop` 终止整个 app，避免容器被自动恢复。

## 7. 优先级

1. Qwen3.5-4B 影像分类闭环。
2. 固定的专项 holdout 和可复现评估。
3. Qwen3.5-4B 第二阶段续训和泛化评估。
4. Qwen3.5-2B 只在明确的资源或对照问题出现时启用。
5. Intern-Decision 只在真实决策标注、医生评审、进度和评测增益均合格后训练与启用。

预算不足时，优先削减 Qwen 第二阶段的泛化数据或推迟补充决策实验，不应削减 01、02、03 的专项 holdout，也不应使用合成决策标签换取“两个模型都训练过”的形式结果。
