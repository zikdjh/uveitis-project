分组续训、数据审计、验证结果与后续判断

结论

  • 正式续训 local-4060-grouped-cont-20261025-01 已完成 150/150 步，状态 ok。
  • 最佳 checkpoint 为第 100 步；第 75 步与第 100 步的 macro-F1 和 JSON 有效率完全相同，按预先定义的 token loss 次级规则选择了第 100 步。
  • 最佳 adapter 在 55 条分组验证集上的任务平均 macro-F1 为 0.865804，总体准确率 0.800，严格 JSON 有效率 100%。
  • 本地 RTX 4060 Laptop 8 GiB 可以完成训练。保留显存峰值为 5.69140625 GiB，峰值分配显存为 5.45239687 GiB，GPU 已释放。
  • 这是第一阶段内部验证结果，不是冻结测试集泛化结论，也不是临床部署批准。

训练调整

  • 从旧 run 第 450 步的最佳 adapter 初始化，但使用新的 AdamW 和新的训练状态。
  • 数据按组留出：13 使用“标签 + 患者 ID”，03 使用“标签 + 去除 aug_ 前缀后的 stem”，02 因缺少患者元数据按图像路径分组。
  • 01 完全退出训练：没有患者 ID，且 4 个来源组全部与测试来源重叠。
  • 排除 03 中 11 条与测试组共享的普通图或增强图。
  • 调度改为轻度类别均衡并轮换组，避免小来源组被反复采样。
  • 验证改为生成后解析 JSON，报告准确率、macro-F1、严格 JSON 有效率、混淆矩阵和分任务指标。
  • 模型选择顺序为任务平均 macro-F1、JSON 有效率、token loss；token loss 仅作为次级指标。

后续建议

  1. 先对最佳第 100 步 adapter 做冻结测试集全量生成式评估；评估代码应复用严格 JSON 解析和分任务 macro-F1，不应再用 token loss 选择。
  2. 冻结测试评估时，01 只能作为“非患者隔离”的参考子集，不能并入泛化结论。
  3. 03 的测试子集需要单独报告，因为存在数据来源和增强图关系限制。
  4. 若要继续提升，优先扩大患者隔离验证集或增加独立外部验证集，而不是继续增加低 token loss 的步数。
  5. 在冻结测试结果出来前，不应把本 adapter 作为临床决策模型发布。
