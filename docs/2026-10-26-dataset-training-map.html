数据集训练映射

影像、检索和决策任务的样本构造与验收指标

HTML 源文件：scripts/docs/.html-source/2026-10-26-dataset-training-map.html

整理日期：2026-10-25

目标：把 model-training/datasets/extracted/ 中的数据转换成可训练的影像分类、影像定位/分割、结构化决策和文本检索样本，用于 Qwen 多模态、Intern-Decision 与 BGE-M3。

1. 先确定训练边界

当前下载的是多来源公开影像数据，不是带完整病史、诊断依据和医生处置的病人队列。因此分三条链路：

链路 训练目标 现有数据支持 不能直接得到
影像模型 病种分类、病灶分割、视盘/黄斑定位、泛化表征 有标签图像、部分掩膜和坐标 真实影像描述、最终诊断、治疗决策
决策模型 输入病例摘要 + 影像描述 + 检索证据，输出结构化决策 只有 ODIR 的年龄、性别和诊断关键词，样本不足 症状、病程、既往史、化验、医生选择
检索模型 检索指南、文献、病例摘要 当前下载主要是图像 当前目录内没有完整文本医学语料

结论：先训练影像分类/定位/分割；决策模型和 RAG 需要补充真实病例文本与审核通过的医学资料后再训练。

2. 训练清单划分

不要把 13 个数据集合成一个分类标签空间。建议生成以下四份清单：

清单 主要数据 适合任务 使用方式
vision_uv 01、02、03 葡萄膜炎专项分类、感染状态分类、病灶分割 目标任务训练与内部测试
vision_aux 04、05、06、07、10 眼底多病种分类、泛化表征、视盘/黄斑定位 辅助预训练或多任务训练
vision_oct_aux 08、09、11、12、13 AS-OCT 房角、青光眼、OCT 形态特征 辅助预训练，不与葡萄膜炎标签合并
rag_corpus / decision_sft 待补充 检索和临床决策 必须在有文本来源和人工审核后建立

4. 具体怎么构造样本

4.1 影像分类样本

视觉语言模型建议使用统一的对话格式：

{
  "id": "uv_oct_0001",
  "dataset": "01_uveitis_oct",
  "image": "model-training/datasets/extracted/01_uveitis_oct/.../Normal 1.jpeg",
  "modality": "oct",
  "task": "classification",
  "patient_group": "01_uveitis_oct:source_folder",
  "split": "train",
  "messages": [
    {"role": "user", "content": "请根据这张眼科影像判断病种，只输出结构化结果。"},
    {"role": "assistant", "content": "{\"label\":\"Normal\",\"confidence\":null,\"requires_review\":true}"}
  ]
}

训练时只把真实标签写进 assistant 答案。confidence 不应由目录名伪造；模型未经过校准前输出 null 或由校准集单独拟合。

不同数据集的分类头规则：

任务 标签集合 训练数据 说明
OCT 四分类 Uveitis、Panuveitis、Normal、RRD-PVR 01 样本很小，建议 5 折患者/来源分组交叉验证
Toxo 二分类 healthy、toxoplasmosis 02 细分 active/inactive 先保留为辅助标签，不强行扩成四个互斥类
五分类 Cataract、Conjunctivitis、Eyelid、Normal、Uveitis 03 仅做原型，先查 SMOTE 生成和重复图
眼底多标签 ODIR 8 类或 RFMiD 45 类 04、06 作为视觉表征预训练；任务头与葡萄膜炎任务分开

4.2 分割和定位样本

  • 02 的 masks/ 与 images/ 按文件名匹配；当前有 144 张图像可匹配到掩膜，只对这些样本做病灶分割。
  • 02 的分类标签表有 1 个文件名差异：标签表列 2809.jpg，实际目录为 2805.jpg。生成清单时必须人工核对原数据后再建立显式映射；无法确认时排除该样本，不能静默错配。
  • 06 RFMiD 原包有 6 处标签 ID 与图像文件名不一致，且缺少可安全的一一映射依据；训练清单排除这些样本，而不是根据序号猜测配对。
  • 07、10 的 Fovea 坐标训练回归或 heatmap 定位。
  • 08、12 的关键点坐标用于房角/黄斑定位辅助。
  • 01、03、04、05、06 没有像素级病灶标注，不做伪造的分割监督。

4.3 患者/来源分组

切分单位不要用单张图片：

  • ODIR：ID 是患者组，左右眼必须同属一个 split。
  • Toxo：优先从文件名或源表恢复患者 ID；无法确认时按 Source 和文件名推断分组，并把无法确认的样本只放入训练集，不进入最终测试。
  • 01、03、05：没有可靠患者 ID，先按文件来源/类别做分组交叉验证；结果标记为“数据集内评估”，不能宣称患者级泛化。
  • 06、07、08、09、10、11、12：优先保留原作者的 train/validation/test。

4.4 去重与泄漏

当前实测：

  • 01 有 1 组完全相同的 SHA256 图像，共 2 个文件。
  • 03 有 1 组完全相同的 SHA256 图像，共 2 个文件。
  • 05 的 2,000 个文件中只有 1,994 张带类别图；1000images/ 内另有 997 张重复副本。

训练前必须做 SHA256 去重和感知哈希相似图检查；03 的 SMOTE notebook 是在完整图像向量上先合成再切分，不能据此认为已有独立测试集。

5. 与三个模型的对应关系

Qwen 多模态模型

第一阶段用 01、02、03 做分类和结构化输出，用 04、05、06 做眼底泛化训练，用 13 的 OCT 子集做形态辅助。仅使用真实标签；没有人工 caption 时，不让模型学习“由模板生成的长篇影像描述”。

建议先做零样本基线，再训练 LoRA。训练损失只计算 assistant 结构化答案，图像编码器先冻结或小学习率解冻。

Intern-Decision 决策模型

需要构造类似下面的 SFT 样本：

{
  "case_id": "external_case_0001",
  "input": {
    "summary": "患者年龄、性别、症状、病程、既往史等",
    "vision": "经审核的影像描述",
    "evidence": ["指南条目", "文献段落", "相似病例"]
  },
  "target": {
    "choice": "一个受约束的处置选项",
    "score": 0.0,
    "noul": "不超过证据边界的说明",
    "requires_human_review": true
  }
}

现有数据不能直接提供 summary、医生处置和 score 的真实标签。ODIR 的年龄、性别、诊断关键词只能做弱关联特征，不能自行生成金标准决策。补齐真实病例文本和医生审核后，再训练 Intern-Decision。

BGE-M3 检索

第一期不建议微调：

  1. 收集指南、专家共识、论文摘要和脱敏病例摘要。
  2. 按段落切块，记录来源、版本、日期和适用范围。
  3. 用 BGE-M3 生成向量，建立本地检索索引。
  4. 用人工问题-证据对评估 Recall@k。

当前下载内容主要是图像，尚不能直接形成可靠的医学 RAG 语料。

6. 推荐的训练顺序

  1. 在 Open UWF 700 上先建立按诊断与 Patient ID 组合的患者组键，再生成 7 类和葡萄膜炎二分类清单；不按图像切分。
  2. 从目录生成 vision_uv、vision_aux、vision_oct_aux 清单，并记录图像路径、标签、来源、患者组、原始 split 和是否重复。
  3. 对 01、02、03 做 SHA256 去重和相似图检查，固定一份不参与训练的 holdout。
  4. 训练三个独立的小型分类基线：OCT 四分类、Toxo 二分类、眼病五分类。
  5. 用冻结视觉编码器或 Qwen LoRA 做结构化分类输出；和零样本基线比较 macro-F1、AUC 与校准误差。
  6. 在 144 张有掩膜的 Toxo 图上训练分割辅助任务，在与任务头解耦的验证集上评估 Dice。
  7. 用 ODIR、RFMiD、眼底/OCT 辅助任务做泛化预训练，不把辅助标签混进葡萄膜炎标签。
  8. 补充并审核病例文本、指南和文献后，再建立 decision SFT 与 RAG 索引。
  9. 三件套联调时，所有输出都带来源证据和 requires_human_review=true。

7. 验收指标

任务 主指标 必须同时记录
01 OCT 四分类 macro-F1、AUC 各类召回率、混淆矩阵、患者/来源分组切分
02 Toxo 二分类 macro-F1、AUC 两个来源分别的成绩
03 五分类 macro-F1 Uveitis 召回率、去重前后差异
分割 Dice、IoU 仅报告 144 张匹配掩膜样本
定位 平均像素误差/归一化误差 按原始 train/validation/test 分开
分类校准 ECE、Brier 不使用未校准的 confidence 做临床阈值
决策模型 JSON 合法率、与医生标注一致率 证据覆盖率、拒答率、人工复核率
检索 Recall@k、MRR 来源可追溯率

8. 当前阻塞项

  • 葡萄膜炎专项数据量小，01 只有 75 张，不能支撑从零训练大模型。
  • 02 的 412 张分类图是眼弓形虫病数据，不等于一般葡萄膜炎队列。
  • 02 的唯一文件名差异（标签表 2809.jpg 对图像 2805.jpg）已按唯一对应关系显式配对并登记在 model-training/datasets/tasks/fundus_toxo_binary/audit.json；02 没有患者 ID，只能做数据集内评估。
  • 03 的类别目录是否全部为原始图像尚未确认，且可能包含 SMOTE 合成样本。
  • 04 没有葡萄膜炎标签。
  • 06 的标签 CSV 存在编码/字符问题，需要清洗后再训练。
  • 13 同时包含 OCT 和胸部 X 光，训练时必须只取 CellData/OCT/。
  • 决策与 RAG 所需的病例文本、医生处置标签、指南版权和来源核验尚缺。
  • 所有数据集的生产使用许可必须逐项核对源站条款。
