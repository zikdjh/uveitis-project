Modal L40S 预算排期

本月与下月预算、训练顺序和数据集安排

Markdown 源文件：model-training/docs/training-budget-plan-modal-l40s-44usd-20261025.md

日期：2026-10-25

目标：在本月 $14、下月 $30 的额度内，优先完成 Qwen3.5-4B 多模态模型的第一阶段 QLoRA 和固定 holdout 评估。Qwen3.5-2B 仅作对照，Intern-Decision-4B 是补充方案，只在真实决策数据、医生复核、进度和预算门槛都通过后占用预算。所有时间均指单卡 L40S 的实际运行时间，不包含本地数据整理时间。

0. 执行结论

  • 4B 正式训练器已完成真实前向、反向、优化器更新、adapter 与 checkpoint 保存验证。
  • 2026-10-25 的 20 步标定使用 20 个真实训练样本，成功 20、跳过 0、OOM 0。
  • 标定函数总耗时 52.1 秒，含模型加载、首步编译和一次 checkpoint 写入；峰值分配显存约 5.58GiB。
  • 稳定优化步约 0.6-1.35s/样本，后续预算仍按 2.0s/样本 保守计算。
  • 本月先做覆盖四类任务和类别的 4B 第一阶段，不用 $14 强行跑完 12,227 个训练样本。
  • Decision 模型当前不训练；现有数据缺少完整病例、医生确认的处置标签和独立决策测试集。

1. 预算口径

沿用项目已有 Modal 成本清单：

资源 保守单价
L40S 约 $1.95/GPU小时
8 核 CPU + 64 GiB 内存 约 $0.89/小时
合计 约 $2.84/小时

按合计价计算：

  • $44 的理论上限约为 15.5 GPU小时。
  • 不把理论值全部花完，计划安排 14.4 GPU小时。
  • 预计花费约 $40.87，保留约 $3.13，用于冷启动、镜像构建、失败重跑和最终核账。

实际以 Modal 账单为准。模型下载、镜像构建、应用空闲、checkpoint 写入和调试也会计费，因此不能只按训练 step 估算。

2026-10-25 已执行的 1 步诊断和 20 步标定都只产生分钟级 GPU 费用。CLI 的累计计量页面不能单独证明剩余额度；只有 Modal 控制台的当前账期余额、团队额度或付款方界面能作为最终依据。每次正式启动前必须再次核账。

2026-10-25 的 focus01 短程实验已结束，阶段性新增计量约 $0.55。step 20 将 01 macro-F1 从 0.3393 提高到 0.5625，但 40 样本中 Intermediate/Posterior 仍为 0 召回，且单类只有 2 个测试样本。该结果仅用于证明数据重加权方向，不改变正式部署 adapter，也不应据此继续盲目续训。

随后从 step 35 受控续训到 step 250，再降到 2.5e-5 续训到 step 313。step 250 的固定 40 样本 01 macro-F1 达 0.6833，02、03 均为 1.0，13 为 0.9；但 step 300 的内部验证损失从 step 100 的 0.018165 回升到 0.030704，因此已主动停止。训练没有用尽用户给定的 $13，而是保留在越界前：

本轮终点 metered_cost $20.35187695
本轮新增 $0.87000000
按用户 $13 额度估算余额 约 $12.13

上述余额是从用户给定额度扣减累计计量得出的执行口径，不是 Modal 控制台 credit 余额。终止状态：没有活跃容器；step 250 和 step 300 均存在于 uveitis-runs。

时间 可用额度 安排时长 预计花费 预留

模型必须顺序训练，不能同时常驻。训练结束后立即停止容器，不使用常驻 GPU 服务。补充决策未达到启用门槛时，其预算保留，不为了消耗排期而训练。

3. 本月：Qwen3.5-4B 第一阶段

3.1 时间安排

阶段 内容 时长 预算
Q0 Modal 镜像、模型加载、单 batch smoke test 0.5 小时 $1.42
Q1 小规模零样本基线 0.2 小时 $0.57
Q2 Qwen3.5-4B QLoRA 第一阶段 2.6 小时 $7.38
Q3 holdout 评估、adapter 导出、checkpoint 校验 0.5 小时 $1.42
合计 3.8 小时 $10.79

训练过程设置 20-30 分钟 checkpoint、2.6 小时硬超时、验证损失 early stopping 和最多连续 3 个样本异常即终止。到时间上限即停止，不为了“跑满 epoch”继续消耗额度。

第一阶段使用 448 x 448 最大像素、1024 token、micro-batch 1、梯度累积 4。2026-10-25 已完成 150 步正式 run；第 100 步验证损失 0.027432 最低，第 150 步回升到 0.031464。因此不再按旧计划盲目扩充到 1,800-3,000 步，下一次训练必须先补 01 的难例和数据质量，再重新确定步数。每个任务和每个标签必须在训练集和验证集里出现，验证集只从 train 行确定性切分，固定 test 不参与训练或选模。

3.2 数据集

本月只取葡萄膜炎专项数据和必要的 OCT 形态辅助数据，不把 13 个数据集的标签合并。

数据 训练用途 计划用量 切分
01_uveitis_oct OCT 四分类 60 训练 / 15 测试 类分层切分；无患者 ID，指标只能标为数据集内评估
02_toxofundus 健康 / 眼弓形虫病二分类 约 330 训练 / 82 测试 优先按患者或来源分组切分
03_eye_five_class 五分类和 Uveitis 阳性识别 约 1,838 训练 / 459 测试 去重后类分层切分；只作原型，不进入最终临床测试
13_zhanglab 的 OCT 子集 OCT 形态辅助 10,000 训练，每类 2,500；1,000 固定测试 使用 CellData/OCT/，排除胸片子目录

第一阶段 train 合计 12,227 张。每张图像保留独立任务提示，不让四类 OCT、五类眼病和 Toxo 二分类共享错误标签空间。

目标输出示例：

{
  "task": "oct_uveitis_4class",
  "label": "Panuveitis",
  "requires_human_review": true
}

不使用目录标签伪造置信度，也不训练模板生成的长篇影像描述。01、02、03 的 holdout 必须在训练前固定，不能根据模型效果反复调测试集。

3.3 本月验收门槛

只有同时满足以下条件，才进入下月第二阶段：

  • smoke test 能完成前向、反向和 checkpoint 保存。
  • Qwen3.5-4B adapter 在 01、02、03 的固定 holdout 上均有可复现结果。
  • 01、02、03 之外，13 OCT 辅助任务必须单独报告，不能把辅助类别当作葡萄膜炎诊断结果。
  • 三类任务的输出 JSON 合法率接近 100%。
  • 已记录每个数据集的来源、去重状态、切分规则和不能宣称的能力边界。
  • 与零样本基线比较后，至少专项任务不出现明显退化。

如果 smoke test 失败或显存不稳，优先减少图像分辨率和序列长度，不追加购买大模型时间。

4.2 Qwen3.5-4B 第二阶段数据

第二阶段在已固定专项 holdout 不变的前提下，增加少量泛化数据：

数据 计划用量 作用
01、02、03 沿用第一阶段训练集 保持葡萄膜炎专项任务为主
04_ODIR 2,000 张唯一图，来自 1,000 个患者，左右眼各 1,000 张 眼底多标签泛化；不把其 8 类解释为葡萄膜炎
06_RFMiD 2 原始训练/验证/测试 509/177/174 45 类长尾眼底泛化
13 OCT 沿用 10,000 张辅助集 保持 OCT 形态能力

采样比例建议为专项数据 60%、OCT 辅助 25%、眼底泛化 15%。泛化任务使用独立 task prompt 和独立评估，不将 ODIR/RFMiD 的类别混入葡萄膜炎四分类。

ODIR 的 full_df.csv 存在以文件名索引的左右眼记录，同一患者可能再次出现；采样脚本已按“患者 + 文件名”去重。训练加载时仍应使用“图像路径 + 任务”作为键，绝不能因此把左右眼拆到不同患者组。

4.3 补充决策模型的启用门槛

当前下载数据没有足够真实的医生处置标签，因此 Intern-Decision 不是无条件训练项。后端默认 APP_DECISION_ENABLED=false，未启用时分析流程直接进入安全校验和人工复核，不影响核心检索闭环。只有满足以下门槛才启动 D0-D2：

  • 至少 300 个脱敏病例，建议 300-500 个训练病例。
  • 至少 80 个验证病例和 80 个独立测试病例。
  • 每例包含病例摘要、人工审核的影像描述、检索证据和医生确认的处置选择。
  • 目标字段统一为 choice、score、noul、requires_human_review。
  • 按患者切分，且病例摘要、影像和证据之间不存在跨集泄漏。

建议的 decision_sft 格式：

{
  "case_id": "case_0001",
  "input": {
    "summary": "年龄、性别、主诉、病程、既往史和关键检查",
    "vision": "经医生审核的影像描述",
    "evidence": ["指南条目", "文献段落", "相似病例"]
  },
  "target": {
    "choice": "受约束的处置选项",
    "score": 0.0,
    "noul": "在证据边界内的说明",
    "requires_human_review": true
  }
}

Intern-Decision 训练配置：

  • 4-bit QLoRA，LoRA rank 16。
  • 最大序列长度 2048，稳定后可试 3072。
  • micro-batch 1，梯度累积 16。
  • 3-5 epochs 或 2 小时硬超时，取较早的早停 checkpoint。
  • 只训练语言层 adapter，不在此阶段训练图像编码器。

如果 11 月前拿不到合格病例和医生确认标签，D0-D2 不启动，E0 也只评估核心链路。这 4.5 小时优先用于 Qwen 的独立测试和错误分析，剩余额度保留；不能用 ODIR 的诊断关键词自动生成 choice、score 或医生决策，也不能用合成标签制造“补充模型已验证”的结论。

补充决策启用前至少应证明：

  • 固定测试集上相对“仅感知 + 检索 + 医生复核”的基线有一致增益。
  • 决策 JSON 合法率和拒答行为可复现。
  • 误诊代价、证据引用和人工升级路径经过医生评审。

6. 节省额度的执行要求

  1. 在本地完成解压、去重、切分、图像缩放和 manifest，Modal 只接收已筛选的训练包。
  2. 训练包只放约 12k-17k 张图，不上传 63 GB 全量数据和无用的预处理副本。
  3. 模型、图像缓存和 adapter 放在持久 Volume；代码镜像固定版本，避免每次重新安装。
  4. 训练和评估分成两个 Modal 函数，评估时只加载 adapter 和必要的 holdout。
  5. 关闭 warm container、定时任务和长期在线 GPU 服务。
  6. BGE-M3 索引在本地 4060 或 CPU 上建立，不占用 Qwen3.5-4B 的 L40S 训练额度。
  7. 每次 Modal 启动前打印 max_runtime、数据规模和预计成本，超过上限自动停止。

2026-10-25 的实测补充：不要在训练容器内启动嵌套 Modal 评估函数。该路径可能生成额外 GPU 作业，失败时还可能被训练循环误认为样本异常。正确流程是只训练并保存 checkpoint，等训练 app 完全停止后，再单独运行评估 app；每次停止都用 modal app stop 终止整个 app，避免容器被自动恢复。

7. 优先级

  1. Qwen3.5-4B 影像分类闭环。
  2. 固定的专项 holdout 和可复现评估。
  3. Qwen3.5-4B 第二阶段续训和泛化评估。
  4. Qwen3.5-2B 只在明确的资源或对照问题出现时启用。
  5. Intern-Decision 只在真实决策标注、医生评审、进度和评测增益均合格后训练与启用。

预算不足时，优先削减 Qwen 第二阶段的泛化数据或推迟补充决策实验，不应削减 01、02、03 的专项 holdout，也不应使用合成决策标签换取“两个模型都训练过”的形式结果。
