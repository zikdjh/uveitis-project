系统使用说明

本地启动、登录入口、核心工作流、管理员维护和常见问题的操作指引

HTML 源文件：scripts/docs/.html-source/2026-10-29-usage-guide.html

前置条件

项要求
GPUNVIDIA RTX 4060（8 GB）或更高；真实模型推理需要 CUDA 版 PyTorch
数据库PostgreSQL 16（必填），Redis（用于会话与队列）
Python3.12+，后端依赖在 backend/.venv，运行服务依赖在 .venv-runtime-smoke
Node.js18+，前端依赖在 frontend/node_modules
模型文件Qwen3.5-4B 基座和第 20 步 adapter 在 model/training/ 下

启动服务

按顺序启动以下四组服务。模型运行服务是可选的，只在真实推理模式时需要。

1. PostgreSQL 和 Redis

cd backend
docker compose up -d postgres redis

2. 模型运行服务（真实推理时启动）

cd qwen3.5-4b
$env:MODEL_RUNTIME_IMAGE_ROOT = (Resolve-Path '..\backend\data\uploads').Path
..\.venv-runtime-smoke\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010

MODEL_RUNTIME_IMAGE_ROOT 必须指向后端的上传目录，否则模型服务会拒绝读取病例影像（403）。启动后访问 http://127.0.0.1:8010/health 确认返回 "status":"ok"。

3. 向量模型服务（使用知识检索时启动）

cd bge-m3
$env:EMBEDDING_INTERNAL_TOKEN = 'replace-with-shared-token'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8011

启动后访问 http://127.0.0.1:8011/health 确认返回 "status":"ok"。backend 通过 APP_VECTOR_PROVIDER=remote 与 APP_RETRIEVAL_SERVICE_URL 调用该服务；不启动时知识检索分支自动跳过，不影响核心流程。

4. 后端

cd backend
.\.venv\Scripts\uvicorn.exe app.asgi:app --host 127.0.0.1 --port 8000

首次部署前复制 .env.example 为 .env 并配置数据库连接。默认 APP_MODEL_MODE=mock 只验证业务链路；切换为 APP_MODEL_MODE=remote 后启用真实模型推理。生产环境建议同时启动 Worker：

.\.venv\Scripts\python.exe -m app.worker

4. 前端

cd frontend
npm install
npm run dev

登录

角色入口说明
医生http://127.0.0.1:5173/login账号由管理员创建；首次登录后可修改密码
管理员http://127.0.0.1:5173/admin/login用户名固定为 root，不可更改；密码只能通过数据库加密哈希记录修改

系统不提供自助注册。医生会话为双 Token 无感刷新（15 分钟 access + 30 天 refresh）；管理员会话为单一 10 分钟短期令牌，每次操作自动续期。

医生工作流

创建病例

  1. 进入 病例 页，点击 新建病例。
  2. 填写患者年龄、性别、受累眼和主诉。
  3. 上传 OCT 或眼底影像（JPG/PNG，最大 25 MB）。
  4. 勾选数据授权确认，点击提交。

辅助分析

  1. 进入病例详情，切换到 辅助分析 标签。
  2. 点击 启动辅助分析。系统按 intake → planning → preprocess → Qwen 判断 → 检索 → 安全复核 → 报告的顺序执行。
  3. 真实推理冷启动约 22 秒，热请求约 3.4 秒。页面会自动轮询任务状态。
  4. 分析完成后病例进入 待复核 状态。

医生复核

  1. 在病例详情的 复核 标签中审阅分析结果。
  2. 填写复核决定（接受/修改/拒绝）、最终印象和备注。
  3. 提交后病例状态变为 已复核。模型输出不会自动成为诊断，必须经医生确认。

查看报告

在 报告 标签中查看医生确认后的结构化报告。报告只展示医生确认的内容，刷新页面后状态不丢失。

管理员操作

账号管理

  1. 进入 账号权限 页。
  2. 点击 创建医生账号，输入用户名、显示名和密码（至少 12 位）。
  3. 需要停用账号时切换状态开关；停用后该账号所有会话立即失效。
  4. 需要重置密码时点击 重置密码；重置后旧会话全部撤销，旧密码不可再登录。

服务配置

  1. 进入 服务配置 页。
  2. 配置外部总结 API（支持 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages 三种协议）。
  3. 配置网络搜索服务商（Tavily、Brave、Serper 等 8 家，可按优先级排序）。
  4. 每个服务可单独启用/禁用；点击 检查连接 验证凭据可用性。
  5. API Key 只写入不回显，保存后立即作用于后端调用链。

知识库管理

  1. 进入 知识库 页。
  2. 上传临床指南或文献（分类：guideline / literature / case / other）。
  3. 向量由独立的 BGE-M3 服务（bge-m3，端口 8011）提供；服务权重在首次检索时加载并常驻内存。
  4. 医生的辅助分析会通过 RAG 检索命中相关条目并注入结果。

活跃会话审计

在 账号权限 页下方查看当前所有在线账号的角色、登录 IP、最近活跃和过期时间。

停止服务

Get-NetTCPConnection -LocalPort 8000,5173,8010,8011 | Stop-Process -Id { $_.OwningProcess }

PostgreSQL 和 Redis 是 Docker Compose 容器，可执行 docker compose down 停止。

常见问题

问题原因解决
后端启动报 APP_DATABASE_URL 错误PostgreSQL 未启动或连接配置缺失先启动数据库，确认 backend/.env 中 APP_DATABASE_URL 正确
分析时 Qwen 判断阶段返回 403模型运行服务的 MODEL_RUNTIME_IMAGE_ROOT 未指向后端上传目录重启模型服务并设置 MODEL_RUNTIME_IMAGE_ROOT 为 backend/data/uploads 绝对路径
分析长时间卡在排队Worker 未启动且 Web 进程任务处理较慢启动独立 Worker：python -m app.worker
页面提示"请先登录"Access 令牌已过期且刷新令牌不可用重新登录即可；医生令牌过期时前端会自动刷新，无需手动操作
管理员端刷新返回 401管理员短期令牌 10 分钟超时重新登录；使用期间系统自动续期，通常不会触发
模型推理超时冷启动加载时间较长后端默认等待 APP_PERCEPTION_TIMEOUT_SECONDS=90；服务恢复后重新分析即可

安全边界

  • 病例文字、患者信息和影像禁止发送至外部公开 API，由后端代码强制校验。
  • 所有外部 API Key 由管理员在服务配置页维护，密钥加密存储只写不读。
  • 模型输出仅供医生参考，不构成诊断结论；系统在分析报告和界面中标注了此边界。
  • 生产部署必须配置 APP_INTEGRATION_SECRET_KEY（至少 32 字符）。
