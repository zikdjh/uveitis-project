分析任务失败恢复回归

运行服务不可用、推理超时、真实回写与服务恢复四个阶段的端到端验收证据

HTML 源文件：scripts/docs/.html-source/2026-10-28-model-runtime-failure-recovery.html

本页补齐 10-27 业务回写之后剩余的失败恢复回归：验证 Qwen 判断分支在运行服务不可用、推理超时和进程重启场景下独立降级，且病例主链路始终完整进入待复核。回归脚本为 model/runtime/scripts/run_recovery_regression.py，证据文件为 model/training/assets/qwen3.5-4b/runtime-recovery-local-4060-20261028-01/recovery_evidence.json。

回归范围

  • 后端使用内存适配器与受控上传目录，业务侧以 model_mode=remote 指向本地运行服务；病例影像为冻结测试集中的一张 OCT 图。
  • 真实阶段使用 RTX 4060 本机运行服务、Qwen3.5-4B 基座与第 20 步 adapter，并启用 X-Internal-Service-Token 内部鉴权。
  • 降级阶段断言：任务结果为 completed、Qwen 阶段为 failed、runtime_metadata 为空、安全标记包含降级说明。
  • 真实阶段断言：Qwen 阶段 completed，runtime_metadata 含模型名、64 位 adapter SHA256、推理时延与峰值显存。

四阶段结果

阶段场景结果耗时
A运行服务端口不可达Qwen 阶段 failed（ConnectError），任务完成并回写确定性摘要，病例进入待复核。2.1 秒
B推理端 8 秒无响应、超时上限 1.5 秒Qwen 阶段 failed（ReadTimeout），降级路径与阶段 A 一致。1.6 秒
C真实运行服务回写返回 CNV 标签；adapter_sha256=00ebeb2c...，峰值保留显存 3.311 GiB，GPU 常驻 4154 MiB。37.6 秒（含首次模型加载）
D停止并重启运行服务后再回写再次完成回写，adapter 指纹与阶段 C 一致，证明服务恢复后链路无需人工干预。37.2 秒（含重新加载）

复跑方式

cd model\runtime
..\..\backend\.venv\Scripts\python.exe -X utf8 -u scripts\run_recovery_regression.py

脚本每次清理并重建 outputs/runtime-recovery-20261028-01/ 工作目录，在 8010 端口拉起运行服务、8011 端口拉起慢响应服务，结束后自动停止进程并重写证据 JSON。需要约 2 分钟与约 4 GiB 显存。

边界说明

本轮测试图在冻结清单中的标注为 Intermediate+Posterior Uveitis，模型返回 CNV，与此前已记录的 CNV/Uveitis 错误边界一致。该回归只证明任务编排、降级与回写链路可靠，不新增准确率、置信度可信度或临床泛化证据；所有模型输出仍必须由医生复核。
