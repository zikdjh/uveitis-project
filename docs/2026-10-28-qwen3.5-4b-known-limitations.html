Qwen3.5-4B 候选已知限制

非临床验证、同源测试、标签范围、校准、外推和隐私边界

HTML 源文件：qwen3.5-4b/assets/freeze-step20-20261028-01/known-limitations.html

一句话结论

这是研究用途的 OCT 四类辅助分类候选，不是临床验证模型，也不是完整葡萄膜炎诊断或病因判断系统。当前证据只能支持“同源冻结测试上优于指定基线”，不能支持真实临床泛化、自动诊断或无医生复核的使用。

临床验证限制

  • 没有任何患者隔离的独立外部验证集。当前 1,000 条冻结测试仍来自同一数据来源，不能替代跨中心外部验证。
  • 没有前瞻性研究、连续入组、多中心验证、临床结局评估或医生-模型对照试验。
  • 没有完成设备、相机、扫描协议、转诊来源和人群分层评价，未知场景下的性能可能显著下降。
  • 没有监管许可、医院准入、质量体系、临床风险管理和正式上市评估。
  • 输出不能用于确诊、排除疾病、决定治疗、安排手术、替代会诊或进行自动分诊。

数据与隔离限制

  • 冻结测试使用 13_zhanglab_oct 的四类 OCT 测试集，每类 250 条；该集合是分组的同源测试，不是独立患者队列。
  • 数据 01 缺少患者 ID，且全部来源组与测试重叠；数据 03 包含原型或增强关系。训练审计排除了这些高风险行，但无法把现存测试集改造成患者隔离外部验证。
  • 错误分析显示 685 个患者/来源组中 50 组存在错误，前 10 个错误组约占全部错误的 24.53%；错误并非完全均匀分散。
  • 当前训练没有统一解决跨数据集重复图像、近重复图像和感知哈希去重问题；不同数据集之间的来源重合风险仍需单独审计。
  • 公开数据集许可和源站条款仍以各自发布方为准；冻结清单不替代对单条数据许可的复核。

标签和任务限制

  • 冻结任务 oct_aux_4class 的类别只有 CNV、DME、DRUSEN、NORMAL，不能直接回答葡萄膜炎亚型、病因、活动度或治疗方案。
  • OCT 结构类别不是临床疾病诊断。CNV、DME、DRUSEN 和 NORMAL 标签不能替代炎症分级、感染筛查、实验室检查或医生综合判断。
  • 该候选没有把患者症状、病史、病程、免疫状态、实验室指标、眼别和既往治疗纳入冻结输入契约；病例文本即使存在于业务系统，也不能被视为模型的已验证输入。
  • UWF 700 的 7 类实验葡萄膜炎 F1 为 0，二分类 adapter 的唯一患者隔离测试 macro-F1 只有 0.338235，54/82 个阴性样本被误报为阳性。UWF 路线未晋级，不能作为当前候选的替代证明。

性能、置信度和外推限制

  • Macro-F1 0.947245 只来自同源冻结测试，不能外推为真实医院性能、患者级性能或跨设备性能。
  • 不同类别并非同步改善：相对第 100 步基线，DRUSEN F1 提升约 0.0651，但 DME 和 NORMAL F1 分别下降约 0.0018 和 0.0105。
  • 主要残余错误是 NORMAL->DRUSEN、DRUSEN->CNV 和 CNV->DME；这些边界不适合用单一置信度阈值自动裁决。
  • 置信度没有做温度缩放、可靠性图、ECE、Brier 分数或临床效用校准。运行烟测已经出现置信度 0 和空 impression。
  • 四类均衡推理 smoke 的 16/16 只证明本地链路和输入覆盖，不能作为准确率、校准或泛化证据。
  • 没有患者级、年龄、性别、地区、疾病严重度、图像质量或相机型号的亚组分析。

运行与工程限制

  • 运行服务是本地研究服务，默认串行执行推理，不是高可用临床推理平台。8 并发烟测衡量的是排队加串行推理，不代表生产吞吐。
  • 已验证环境是单机 RTX 4060 Laptop 8 GB；其他 GPU、量化库版本、CUDA 版本和显存布局未完成等价验证。
  • 运行服务依赖本地基座、adapter 和图像根目录。路径缺失或权限错误时返回降级或 503，业务侧必须继续执行跳过逻辑，不能阻塞病例复核。
  • 后端默认仍可使用 mock 模式；真实模型启用需要显式配置，启用后也必须允许超时、服务不可用和推理失败时独立降级。
  • 当前未完成生产级密钥托管、HTTPS、监控告警、审计留存、容量规划、滚动升级和故障演练部署。

隐私和安全边界

  • 病例影像、原始病例文本、患者标识和可反推信息不得发送给外部总结模型、网络搜索服务或任何第三方 API。
  • 外部 API 只能接收管理员配置的脱敏、聚合、无影像问题；该规则由后端硬边界和测试共同约束。
  • 模型输出不构成医疗建议，不向患者直接展示为诊断结论；所有结果进入医生复核流程。
  • 不得把 adapter、评估预测、病例截图或原始图像作为公开仓库内容；仓库和发布边界需要继续审计。

允许用途

  • 本地工程联调、接口验收、资源测量和回归测试。
  • 在医生复核下作为研究型第二意见，帮助验证业务编排、回写、降级和审计链路。
  • 作为后续患者隔离验证、外部验证和决策模型研究的历史基线。

禁止用途

  • 自动诊断、自动排除疾病、自动制定治疗方案或替代医生判断。
  • 面向患者直接给出确定性结论，或用于保险、就业、法律、分诊和资源分配等高风险决策。
  • 把零置信度、空 impression、truncated 输出解释为正常或低风险。
  • 用已消费冻结测试集继续调参、选择 checkpoint 或包装成新的准确率证据。
  • 在未完成外部验证和合规评估前称为“已临床验证”“可用于诊断”或“可部署产品”。

解除限制前必须具备

  1. 患者隔离的独立外部验证集，并明确来源、入排标准、采集设备和标签定义。
  2. 医生确认的结构化标签、双人复核或仲裁记录，以及标签一致性评估。
  3. 置信度校准、亚组性能、失败模式、拒识策略和临床效用评估。
  4. 本地数据边界、审计、访问控制、密钥托管和故障降级的正式验证。
  5. 完成适用的临床、伦理、隐私、法规和质量审查后，才能讨论任何临床发布。

本限制页与 freeze-manifest.json、runtime-contract.json 和 model-card.html 共同构成第 20 步候选的冻结边界；任何后续训练、adapter 替换或指标更新都应产生新的冻结标识，而不是覆盖本记录。
