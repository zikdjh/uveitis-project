智能体执行链路规划

病例接入、影像感知、检索、决策和安全复核链路

HTML 源文件：scripts/docs/.html-source/2026-10-23-agent-execution-chain.html

目标：把诊断系统拆成一条可审计、可回滚、可扩展的智能体链路。Qwen3.5-4B 微调模型只负责结构化判断，不负责最终报告；RAG、决策模型、网络搜索和外部总结都可以独立跳过，不阻塞主链路。

1. 总体链路

用户/医生输入
  -> IntakeAgent
  -> PreprocessAgent
  -> RouterAgent
  -> QwenJudgmentAgent(可选：Qwen3.5-4B 微调判断)
  -> RetrievalAgent(可选：BGE-M3 + zvec RAG)
  -> DecisionAgent(可选：补充决策模型)
  -> SearchAgent(可选：8 家主流搜索 API，按管理员顺序降级)
  -> ExternalSummaryAgent(可选：外部 API 总结梳理)
  -> SafetyAgent
  -> ReportAgent
  -> ReviewAgent
  -> LearningAgent

核心思想：

  • 每个节点只做一件事。
  • 每个节点都有明确的输入/输出 JSON。
  • Qwen 判断、RAG、决策、搜索和外部总结均为增强组件，各自有超时和异常边界。
  • 任一增强组件不可用或输出不合法时，只记录 skipped 或 failed，主流程继续进入安全校验和医生复核。
  • 医生复核永远保留在链路里。

2. 节点职责

1. IntakeAgent

接收用户输入。

输入：

  • 患者基本信息
  • 主诉
  • 病史
  • 影像文件
  • 已有检查结果

输出：

{
  "case_id": "uuid",
  "patient": {
    "age": 41,
    "sex": "F"
  },
  "complaint": "眼红、视物模糊 3 天",
  "images": [
    {"type": "fundus", "path": "/cases/uuid/fundus_1.jpg"}
  ],
  "consent": true
}

2. PreprocessAgent

负责标准化和脱敏。

任务：

  • 图像格式转换
  • 去标识化
  • 影像质量检查
  • OCR 已有报告
  • 生成统一 metadata

输出：

{
  "quality": "pass",
  "images": [
    {"type": "fundus", "path": "/clean/uuid/fundus_1.jpg", "laterality": "OD"}
  ],
  "ocr_text": "...",
  "risk_flags": []
}

3. RouterAgent

决定使用哪条模态路径。

可路由到：

  • fundus / UWF 路径
  • OCT 路径
  • anterior segment 路径
  • text-only 路径

输出：

{
  "route": ["fundus", "text"],
  "confidence": 0.94
}

4. QwenJudgmentAgent

主力模型：Qwen3.5-4B 微调 adapter。该节点只做结构化判断，不直接生成最终临床报告。

任务：

  • 影像分类与受限标签判断
  • 病灶描述与结构化发现
  • 输出置信度和人工复核标记

输出：

{
  "findings": [
    {
      "finding": "vitreous opacity",
      "location": "posterior chamber",
      "confidence": 0.82
    }
  ],
  "label": "oct_aux_4class::cnv",
  "confidence": 0.82,
  "requires_human_review": true
}

5. RetrievalAgent

状态：可选增强。向量化模型：BGE-M3；向量数据库：zvec。

zvec 是嵌入式本地向量数据库，承担向量、标量字段和过滤条件的持久化检索，不另外部署独立向量服务。BGE-M3 只负责把文本转换为 DIM 维向量。

BGE-M3 从 ModelScope 的 BAAI/bge-m3 下载到项目本地，在 CPU 上以 FP32 运行，默认使用稠密向量。模型首次检索时惰性加载，不在 API 启动阶段占用内存。切换 embedding provider 后必须重建 zvec 索引。

本项目的集合为 uveitis_knowledge，默认维度 1024，使用 HNSW + COSINE。zvec 写入为单进程独占，一个集合不应由多个 API worker 同时打开；横向扩容时应改为独立检索服务或按分片拆分集合。

任务：

  • 检索指南
  • 检索相似病例
  • 检索文献
  • 提供可引用证据

输出：

{
  "evidence": [
    {
      "id": "guideline_2026_014",
      "source": "RCOphth Uveitis dataset",
      "score": 0.87,
      "snippet": "..."
    }
  ]
}

6. DecisionAgent

状态：可选补充方案，默认关闭。是否启用由项目进度、真实决策标注质量和试点评测决定，不阻塞核心流程。

候选模型：Intern-Decision-4B；Kev-4B 作为对照，不默认常驻。

输入：

  • QwenJudgmentAgent 输出
  • RetrievalAgent 证据
  • 患者 metadata
  • 临床主诉

输出：

{
  "primary_class": "posterior_uveitis",
  "differential": [
    {"class": "toxoplasmosis", "score": 0.62},
    {"class": "VKH", "score": 0.24}
  ],
  "urgency": "medium",
  "recommended_action": [
    "fundus fluorescein angiography",
    "infectious workup"
  ],
  "evidence_ids": ["guideline_2026_014"],
  "confidence": 0.71
}

7. SearchAgent

状态：可选增强。统一适配 Tavily、Brave Search、Serper、Google Programmable Search (CSE)、Bing Web Search、Exa、Perplexity 和自建 SearXNG，输出可引用的网页证据。服务商密钥、启用集合和尝试顺序由管理员在服务配置页维护，医生没有读写权限。

  • 默认不把主诉等临床文本发送给外部搜索 API。
  • 查询词优先来自 Qwen 判断标签、补充分类和固定医学检索词。
  • 单个提供方失败时继续尝试其他提供方；全部失败只记失败，不改变主流程。

8. ExternalSummaryAgent

状态：可选增强。支持 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages 三种接口，对结构化判断、RAG 证据、搜索证据和补充分类进行总结梳理。管理员维护协议、地址、模型与密钥，密钥只写不读。

  • 只接收结构化结果和证据，不接收原始影像。
  • 默认不发送主诉和病史；如需发送必须显式配置并完成外部数据处理评估。
  • 外部总结不是诊断，外部 API 不可用时自动使用确定性回退摘要。

9. SafetyAgent

这是一个确定性校验节点，不是大模型。

检查：

  • JSON schema 是否合法
  • 是否缺少关键信息
  • 是否给出高风险但无证据的结论
  • 是否超出辅助诊断边界
  • 是否需要转人工

失败时：

  • Qwen 判断、RAG、搜索、补充决策或外部总结不可用时只跳过该分支，不阻断其他增强分支和医生复核
  • 任一增强模块输出不合法时，不把该输出写入最终判断，保留错误或跳过状态供审计
  • 不把外部 API 作为唯一的结论来源

10. ReportAgent

生成医生端报告和患者友好说明。

输出：

  • 医生报告
  • 患者摘要
  • 检查建议
  • 证据引用

11. ReviewAgent

医生复核节点。

记录：

  • 是否接受
  • 修改后的诊断
  • 不同意原因
  • 是否允许入训练集

12. LearningAgent

后台节点，不在线上实时跑。

任务：

  • 复核结果入库
  • 构建微调样本
  • 触发下一轮训练
  • 记录模型版本

3. Modal 部署结构

服务 类型 GPU 说明
intake API 0 轻量
preprocess Worker 0/1 可用 CPU 完成
router API 0 小模型即可
qwen_judgment Inference L40S Qwen3.5-4B 只输出结构化判断
retrieval Inference L4/T4 BGE-M3
web_search External API 0 Tavily / Brave / Serper / Google CSE / Bing / Exa / Perplexity / SearXNG，可多提供方降级
decision Inference（按需） L40S 补充方案通过门槛后再启用
external_summary External API 0 OpenAI Responses / OpenAI Chat Completions / Anthropic Messages；失败时使用确定性摘要
safety API 0 确定性规则
report API 0/1 文本生成
review API 0 医生复核
learning Batch L40S 训练

4. 状态存储

存储 用途
Volume: raw 原始影像
Volume: clean 清洗后影像
Volume: models 模型和 adapter
Volume: index 向量索引
Volume: runs 日志、评估、训练输出
DB: cases 病例状态
DB: feedback 医生复核

5. 失败与回退

失败点 处理
图像质量不合格 返回重拍/补图，不强行诊断
Qwen 判断不可用或超时 跳过 Qwen 分支，其他增强分支和主链路继续
RAG 索引为空或检索失败 跳过 RAG，保留证据缺口标记
搜索 API 部分或全部不可用 继续尝试其他提供方；全部失败时跳过搜索分支
补充决策未启用或不可用 跳过该分支，直接进入安全校验和人工复核
Decision JSON 不合法 丢弃该输出并标记失败，不写入最终判断
外部总结不可用 使用本地确定性摘要，报告与复核照常完成
任一增强模块置信度低 保留人工复核标记，不让模型替代医生判断

6. 最小可用版本 MVP

主链路只需要保留：

Intake -> Preprocess -> Safety -> Report -> Review

Qwen 判断、RAG、网络搜索、补充决策和外部总结都是可插拔增强分支。任一分支不可用时记录跳过状态，不改变主链路状态。

外部 API 默认不接收原始影像，也不默认接收主诉、病史等临床文本；启用外部数据处理前必须完成隐私与合规评估。

7. 关键配置

配置 作用
APP_QWEN_JUDGMENT_ENABLED启用 Qwen3.5-4B 微调判断分支
APP_PERCEPTION_SERVICE_URLQwen 判断服务地址，调用 /v1/judge
APP_RAG_ENABLED启用本地 BGE-M3 + zvec 检索
APP_DECISION_ENABLED启用补充决策模型，默认关闭
管理端网络搜索配置管理员维护服务商启用状态、尝试顺序、密钥、地址和最大结果数；运行时从数据库读取，环境变量不提供运营配置入口
管理端外部总结配置管理员维护协议、地址、模型、密钥和临床文本发送开关；启用状态与敏感性开关分开保存
APP_SUMMARY_TIMEOUT_SECONDS设置外部总结请求的部署级超时，不包含凭据
APP_INTEGRATION_SECRET_KEY用于 AES-GCM 加密数据库中的服务密钥；生产环境必须配置至少 32 个字符

8. 管理员配置与权限

外部 API 与网络搜索 API 的配置权限只授予系统管理员。管理端提供 integration:read 与 integration:manage 对应能力；医生可通过 system:read 查看总结与搜索是否启用，但不能查看 API 地址、模型、服务商顺序、掩码提示或修改任何服务配置。

  • 配置保存在 PostgreSQL 的 integration_settings，管理员后台不使用 SQLite 持久化。
  • API Key、搜索 Key 和自建实例凭据只写不读；返回字段仅表示“已配置”，不回传加密值或密钥原文。
  • 每次更新递增 revision 并写入审计事件 integration_config_update；并发覆盖使用 409 冲突保护。
  • 配置检查需要管理员权限；搜索服务会执行真实连通性检查，总结服务只校验协议、地址、模型与密钥是否齐全。检查失败只显示错误，不把密钥写入日志、审计详情或前端响应。
  • 启用搜索不等于发送临床文本：主诉发送开关独立且默认关闭。外部总结的临床文本开关同样独立且默认关闭，原始影像始终不发送。
